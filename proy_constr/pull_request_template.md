## Checklist de Revisión

### Estructura y Calidad
- [ ] ¿Los nombres de variables/funciones son descriptivos?
- [ ] ¿El componente está bien modularizado?
- [ ] ¿Se siguen los principios DRY/KISS?
- [ ] ¿El código es legible sin comentarios excesivos?

### Funcionalidad
- [ ] ¿La implementación cumple con los criterios de aceptación?
- [ ] ¿Se manejan casos borde (usuario no autenticado, mobile)?
- [ ] ¿La accesibilidad está considerada (aria labels)?

### Pruebas
- [ ] ¿Las pruebas cubren casos felices y errores?
- [ ] ¿Los tests son independientes y determinísticos?
- [ ] ¿Se usaron mocks apropiadamente?

### Convenciones
- [ ] ¿El commit message sigue conventional commits?
- [ ] ¿El formateo es consistente?
- [ ] ¿No hay archivos temporales o secretos?
